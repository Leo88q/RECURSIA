# RECURSIA — модель безопасности и сверка с чек-листом

Документ сопоставляет каждый пункт чек-листа безопасности (части 0–3, разделы A–W)
с конкретным механизмом в коде. Статусы:

- ✅ **закрыто в коде** — есть конкретная проверка/конструкция, указан файл;
- 🧪 **закрыто тестом/CI** — свойство проверяется автоматически;
- 📋 **процедура** — закрывается операционным регламентом (см. `docs/DEPLOY.md`);
- ⚪ **неприменимо** — механизма нет в игре (объяснено почему);
- ⚠️ **принятый риск / не сделано** — честно указано.

Пути: `P/` = `programs/recursia/src/`, `SDK/` = `packages/sdk/src/`.

---

## Часть 0. Архитектурные решения, снимающие целые классы атак

| Решение | Какие классы атак снимает |
|---|---|
| Симуляция клеточного автомата **считается в контракте** (`P/sim.rs`), клиент ничего не «сообщает» | подмена счёта / score injection, фальшивые результаты с сервера, backend replay |
| **Нет бэкенда с ключами.** Keeper — permissionless, любой может его запустить | утечка серверного ключа, nonce/replay на бэкенде, компрометация API |
| Игра **детерминирована** (Life-подобные правила), случайность не нужна | манипуляция RNG, VRF-атаки |
| Эмиссия = **ребейт от реально сожжённого** и ≤ `rebate_cap` (90%) | фарм эмиссии самоигрой, wash-фарм, флеш-лоан фарм |
| Mint authority **отозван навсегда** в `genesis`, freeze authority не задавался | бесконечный минт, заморозка кошельков |
| Все ИИ-лимиты — **в контракте** (`AgentPermit`), а не в промпте | prompt injection, confused deputy, «ИИ слил кошелёк» |
| Оптимистичные fraud proofs **сознательно убраны** | окно челленджа, liveness-атаки на челленджеров |

## Часть 2. Экономика, игровые эксплойты, клиент (разделы M–S)

| Пункт | Статус | Как закрыто |
|---|---|---|
| Sybil-фарм эмиссии | ✅🧪 | награда мира ≤ 90% его сожжённого → каждый сибил платит больше, чем получает (`econ-sim` I2/I3) |
| Wash trading территорий | ✅🧪 | покупка у самого себя запрещена; налог Харбергера на объявленную цену; econ-sim I4 |
| Flash-loan / манипуляция ценой (TWAP) | ✅ | в контракте нет оракулов цены и нет залогового кредитования; награда считается по сожжённому за **прошлую** эпоху |
| Race conditions / dup-баги (Aurory, Sunflower) | ✅ | Solana сериализует запись в аккаунт; `init_if_needed` только для детерминированных PDA; cooldown'ы; награда эпохи клеймится один раз (`prev_claimed`) |
| Atomic craft (частично выполненное действие) | ✅🧪 | одна инструкция = одно атомарное действие; в модели все проверки до эффектов |
| Batch-авторизация (пачка инструкций от чужого имени) | ✅ | каждая инструкция требует собственную подпись владельца; агент — только в рамках permit |
| Score injection | ✅ | счёт = население клеток, посчитанное контрактом |
| DAO-спам (Synthetify) | ✅ | «восстание» — не произвольное предложение, а фиксированное действие; нужен ≥ 8 голосов держателей и 66.67%; одно восстание за раз; cooldown 216 000 слотов |
| Инсайдеры / пре-майн | ✅📋 | распределение 45/10/45 фиксировано в `genesis`; казна тратится только через публичный timelock |
| Экономическая симуляция до мейннета | 🧪 | `npm run econ` — 5 сценариев × N сидов, 7 инвариантов, в CI |
| Fuzz / invariant тесты | 🧪/⚠️ | инварианты в модели + econ-sim + векторы Rust↔TS. **Trident-фаззинг самого Rust-кода не подключён** — рекомендуется перед мейннетом |
| simulateTransaction-превью перед подписью | ✅ | `app/src/chain.tsx`: каждая транзакция симулируется, пользователю показываются логи/ошибка до подписи; keeper тоже симулирует |
| CSP | ✅ | строгий CSP в prod-сборке (`app/vite.config.ts`), `object-src 'none'`, `frame-ancestors 'self'`; кастомный RPC добавляется в allow-list явно |
| Pinning npm, lockfile, запрет install-скриптов | ✅🧪 | `.npmrc`: `save-exact`, `ignore-scripts`; `npm ci`; `npm audit` в CI |
| Supply chain @solana/web3.js 1.95.6/1.95.7 (бэкдор) | ✅🧪 | зафиксирована версия **1.99.0**; CI проверяет, что скомпрометированных версий нет в дереве |
| Утечка ключей | ✅📋 | `.gitignore` для ключей и `.env`; keeper читает ключ из файла с проверкой прав 600, никогда не логирует |
| DNS hijack фронтенда | 📋 | DNSSEC + registry lock, CAA; фронт не хранит секретов; на сайте опубликован PROGRAM_ID, кошелёк показывает, какую программу вызываем |
| NFT как авторизация | ⚪ | авторизация только по подписи и PDA; NFT в игре нет |
| NFT authorities | ⚪ | NFT нет |

## Часть 3. ИИ-агенты и новые векторы (разделы T–W)

| Пункт | Статус | Как закрыто |
|---|---|---|
| Prompt injection (Bankrbot/Grok) | ✅ | встроенные агенты (`SDK/agents.ts`) — **не LLM** и не читают внешний текст: вход — только ончейн-числа. Даже LLM-агент стороннего игрока ограничен permit'ом |
| Лимиты в контракте, а не в промпте | ✅ | `AgentPermit`: scope (plant/acquire), `max_spend_per_epoch`, `max_price`, `allowed_world`, срок ≤ 30 дней, отдельный vault; `charge_permit` в `P/instructions/common.rs` |
| Confused deputy | ✅ | агент тратит **только** vault своего permit'а; территории записываются на владельца; вывести средства агент не может — только владелец (`withdraw_permit`/`revoke_permit`) |
| Memory poisoning | ✅ | у агентов нет памяти вне ончейн-состояния; состояние каждый раз читается заново |
| Auto-approve | ✅ | клиент никогда не подписывает сам: всегда превью + подтверждение в кошельке; keeper подписывает только инструкции из allow-list программ |
| MCP tool poisoning | ⚪/📋 | проект не поставляет MCP-сервер; если появится — только read-only инструменты, транзакции подписываются человеком |
| Скорость эксплуатации ИИ | ✅ | ущерб от скомпрометированного агента ограничен лимитом эпохи; пауза гейм-плея доступна multisig'у без timelock (но не двигает средства) |
| ИИ-брендированные дрейнеры | 📋 | в UI и README: официальный домен, PROGRAM_ID, «мы никогда не просим seed-фразу»; приложение запрашивает только подпись транзакций своей программы |
| Скрытый unicode в коде | ✅🧪 | `scripts/check-unicode.mjs` в CI; имена миров/модулей в контракте фильтруются от управляющих и невидимых символов |
| Durable nonce + multisig social engineering (Drift 2026, нулевой timelock) | ✅📋 | timelock нельзя обнулить; `expected_nonce` в `execute`; регламент: подписанты сверяют хэш предложения независимо, никаких «срочных» подписей |

## Принятые риски и что осталось до мейннета

1. ⚠️ **Внешний аудит не проводился.** Код готов к аудиту (см. `docs/DEPLOY.md`, чек-лист «перед мейннетом»).
2. ⚠️ **Trident-фаззинг Rust-кода не подключён**: сейчас инварианты проверяются на эталонной модели и cross-impl векторах.
3. ⚠️ `npm audit` показывает moderate-уязвимости в цепочке `jayson → stream-json` (транзитивно через `@solana/web3.js`). Эксплуатируется только при парсинге недоверенного JSON-RPC ответа в Node. Кросс-мажорный override опаснее самой уязвимости; риск принят до обновления web3.js.
4. ⚠️ Экономика: по результатам `econ-sim` при дефолтных параметрах средний ИИ-игрок за 6–20 эпох слегка в минусе (игроки получают ~45% сожжённого). Это осознанный дефляционный дизайн, но параметры (`harberger_bps`, `rebate_cap_bps`, `tick_cost`) стоит откалибровать на devnet с живыми игроками. Меняются только через 48-часовой timelock.
