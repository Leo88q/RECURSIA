# RECURSIA — модель безопасности и сверка с чек-листом

Документ сопоставляет каждый пункт чек-листа безопасности (части 0–3, разделы A–W)
с конкретным механизмом в коде. Статусы:

- ✅ **закрыто в коде** — есть конкретная проверка/конструкция, указан файл;
- 🧪 **закрыто тестом/CI** — свойство проверяется автоматически;
- 📋 **процедура** — закрывается операционным регламентом (см. `docs/DEPLOY.md`);
- ⚪ **неприменимо** — механизма нет в игре (объяснено почему);
- ⚠️ **принятый риск / не сделано** — честно указано.

Пути: `P/` = `programs/recursia/src/`, `SDK/` = `packages/sdk/src/`.

---

## Часть 0. Архитектурные решения, снимающие целые классы атак

| Решение | Какие классы атак снимает |
|---|---|
| Симуляция клеточного автомата **считается в контракте** (`P/sim.rs`), клиент ничего не «сообщает» | подмена счёта / score injection, фальшивые результаты с сервера, backend replay |
| **Нет бэкенда с ключами.** Keeper — permissionless, любой может его запустить | утечка серверного ключа, nonce/replay на бэкенде, компрометация API |
| Классические миры **детерминированы**; в квантовых мирах единственный источник случайности — хеш **заранее назначенного** слота из `SlotHashes` (не `Clock`, не сервер, не аргумент транзакции) | подмена RNG сервером, выбор энтропии кранкером/наблюдателем, «переждать» плохой исход |
| Награда эпохи = **ребейт от реального вклада в пул** и ≤ `rebate_cap` (90%); 20% студии не возвращаются никогда | фарм наград самоигрой, wash-фарм, флеш-лоан фарм |
| Игра **не владеет mint authority** SKR и не может минтить/сжигать; freeze authority у SKR нет (`initialize` это проверяет); мейннет-сборка принимает только официальный `SKR_MINT` | бесконечный минт, заморозка кошельков, подмена токена подделкой |
| Все ИИ-лимиты — **в контракте** (`AgentPermit`), а не в промпте | prompt injection, confused deputy, «ИИ слил кошелёк» |
| Оптимистичные fraud proofs **сознательно убраны** | окно челленджа, liveness-атаки на челленджеров |
| **Нейтральные миры** рождаются без архитектора (`architect = default`, `liberated`), SWAP **обязателен для клеток**, а не для людей | рента правителя, «побег» от проигранной ставки перепродажей клетки на свой второй кошелёк |
| Законы игроков — это **данные** (битовые маски), проверяемые `validate_rule`/`validate_quantum_rule`, а не пользовательский код | исполнение чужого кода в контракте, CU-бомбы в «модулях» |

## Часть 2. Экономика, игровые эксплойты, клиент (разделы M–S)

| Пункт | Статус | Как закрыто |
|---|---|---|
| Sybil-фарм наград | ✅🧪 | награда мира ≤ 90% его вклада в пул, а 20% доли студии не возвращаются → каждый сибил теряет ≥ 28% трат (`econ-sim` I2/I3) |
| Wash trading территорий | ✅🧪 | покупка у самого себя запрещена; налог Харбергера на объявленную цену; econ-sim I4 |
| Flash-loan / манипуляция ценой (TWAP) | ✅ | в контракте нет оракулов цены и нет залогового кредитования; награда считается по вкладу в пул за **прошлую** эпоху |
| Race conditions / dup-баги (Aurory, Sunflower) | ✅ | Solana сериализует запись в аккаунт; `init_if_needed` только для детерминированных PDA; cooldown'ы; награда эпохи клеймится один раз (`prev_claimed`); суперпозиция — одна на клетку (PDA `init`), коммит ставит cooldown посадки на обе запутанные клетки, коллапс закрывает PDA (двойной коллапс невозможен); клетка, проданная во время суперпозиции, не перезаписывается |
| Atomic craft (частично выполненное действие) | ✅🧪 | одна инструкция = одно атомарное действие; в модели все проверки до эффектов |
| Batch-авторизация (пачка инструкций от чужого имени) | ✅ | каждая инструкция требует собственную подпись владельца; агент — только в рамках permit |
| Score injection | ✅ | счёт = население клеток, посчитанное контрактом |
| DAO-спам (Synthetify) | ✅ | «восстание» — не произвольное предложение, а фиксированное действие; нужен ≥ 8 голосов держателей и 66.67%; одно восстание за раз; cooldown 216 000 слотов |
| Инсайдеры / пре-майн | ✅📋 | своего токена и пре-майна нет; доход студии — только 20% трат игроков в PDA `treasury`, тратится только через публичный timelock 48 ч; пул наград админ вывести не может |
| Экономическая симуляция до мейннета | 🧪 | `npm run econ` — 7 сценариев (включая «квантовые миры» и «нейтральные + законы») × N сидов, 11 инвариантов (I8 — утаивание исхода невыгодно, на изолированных близнецах; I9 — квантовый эскроу, включая премии SWAP, не утекает; I10 — нейтральный мир никогда не получает правителя; I11 — роялти капает только используемым законам), в CI |
| Квантовый эскроу | ✅🧪 | `quantum_escrow` (залоги суперпозиций + премии и бонусы SWAP) входит в `world_ledger_total` → `assert_world_solvent` после каждой квантовой и SWAP-инструкции; в модели `check()` сверяет эскроу с суммой залогов и открытых сделок |
| SWAP: гонки и дубли | ✅🧪 | одна сделка на упорядоченную пару (PDA `init`); `swap_resolve`/`swap_cancel` закрывают аккаунт; премия — pull-платёж в `claims_vault` → `Player.claimable`; бонус резолвера из эскроу, не из воздуха |
| Законы игроков | ✅🧪 | клиентская `lawError` зеркалит контракт (тест «lawError mirrors the contract»); роялти ≤ 5% и неизменяемо; модуль в модели собирается только из явных полей (регресс «наследование `accrued` родителя» пойман инвариантом claims в тесте) |

## Принятые риски и что осталось до мейннета

1. ⚠️ **Внешний аудит не проводился.** Код готов к аудиту (см. `docs/DEPLOY.md`, чек-лист «перед мейннетом»).
2. ⚠️ **Trident-фаззинг Rust-кода не подключён**: сейчас инварианты проверяются на эталонной модели и cross-impl векторах.
3. ⚠️ `npm audit` показывает moderate-уязвимости в цепочке `jayson → stream-json` (транзитивно через `@solana/web3.js`). Эксплуатируется только при парсинге недоверенного JSON-RPC ответа в Node. Кросс-мажорный override опаснее самой уязвимости; риск принят до обновления web3.js.
4. ⚠️ Экономика: по результатам `econ-sim` при параметрах по умолчанию средний ИИ-игрок за 6 эпох теряет около 6% стартового кошелька (награды возвращают 20–25% вклада в пул за 6 эпох при пустом стартовом пуле). Это «игра как сервис»; параметры (`harberger_bps`, `rebate_cap_bps`, `tick_cost`, `emission_rate_bps`) и стартовое пополнение пула через `fund_reward_pool` стоит откалибровать на devnet с живыми игроками. Параметры меняются только через 48-часовой timelock.
5. ⚠️ Квантовый слой: энтропия из `SlotHashes` смещаема лидером слота на ~1 бит (см. раздел K). Для mainnet со ставками выше дефолтных — заменить `quantum_seed` на VRF. Пауза не блокирует `quantum_observe`/`quantum_collapse` (залог не может застрять), но блокирует `quantum_decohere` (нельзя потерять залог, пока действовать запрещено).
6. ⚠️ SWAP в нейтральных мирах использует ту же энтропию `SlotHashes` (то же ~1 бит влияния лидера слота). Премия и сбор малы относительно награды за блок; для крупных сделок — VRF. Жизнеспособность законов в Лаборатории — офчейн-прогноз и ни на что в контракте не влияет. Пауза блокирует `swap_offer`/`swap_accept`, но не `swap_resolve`/`swap_cancel`: уже согласованные сделки и возвраты не застревают.
